\chapter{Security Measures, Access Rights, and Data Protection}

\section{Security Objectives}
The implementation targets secure access control, upload validation, traceability of sensitive operations, and route-level protection for privileged actions.

\subsection{Data Integrity Protections}
\begin{itemize}
\item relational integrity through foreign keys.
\item enum restriction for state-like fields.
\item range checks for score values.
\item conditional check for rejection reason.
\end{itemize}

\section{Security Limitations and Mitigations}
\begin{itemize}
\item Email provider integration is mock/log-based in current implementation.
\item Encryption-at-rest configuration is deployment-level and should be documented in hosting setup.
\item External model dependencies introduce reliability and trust boundary concerns.
\item Additional penetration and threat-model testing is recommended before production rollout.
\end{itemize}

\section{Compliance Preparedness}
The design supports compliance documentation through clear workflow stages, audit traces, and report-level decision summaries. Final deployment must complete operational controls such as TLS termination, key rotation, retention policy governance, and monitoring procedures.
